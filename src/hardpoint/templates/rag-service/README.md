# {{ project_name }}

A question-answering HTTP service over the documents in `docs/`, generated by
`hardpoint init --template rag-service` (hardpoint {{ hardpoint_version }}).

## Run it locally

```bash
cp .env.example .env              # add OPENAI_API_KEY
docker compose up -d qdrant       # or point QDRANT_URL at your own
hardpoint doctor                  # config, keys, extras, index, dimensions
hardpoint ingest run --plan       # what would be embedded, and what it costs
hardpoint ingest run
hardpoint serve                   # http://localhost:8000/docs
```

No key and no Docker? `HARDPOINT_ENV=offline` swaps in deterministic local fakes
and a file-backed index; everything below works with nothing leaving the machine.

```bash
curl -s localhost:8000/query -H 'content-type: application/json' \
     -d '{"question": "How do I rotate an API key?"}'
curl -sN localhost:8000/query/stream -H 'content-type: application/json' \
     -d '{"question": "What are the rate limits?"}'
```

## Routes

| Route | What it does |
|---|---|
| `POST /query` | The whole `Answer` as JSON: text, citations, usage and cost, degradations, run manifest. |
| `POST /query/stream` | Server-sent events: `delta` events as text is generated, then one `done` event with citations, usage and degradations. |
| `GET /healthz` | Liveness. |
| `GET /readyz` | Readiness: every index reachable, embedding credentials accepted. |
| `GET /metrics` | Prometheus text (with `observability.metrics: {type: memory}`). |

Send `x-request-id` and it becomes the run id: the trace, the logs and the
response all carry it.

## What is where

| Path | What it is | Change it when |
|---|---|---|
| `pipelines/rag.py` | The pipeline, step by step. | You change the retrieval strategy. |
| `service/app.py` | The HTTP layer. | You add auth, tenancy, routes. |
| `prompts/` | The answer prompt, and the abstention and refusal wording. | Always: this is your product's voice. |
| `config/base.yaml` | Providers, index, guards, cache, budgets. | You switch provider or tune retrieval. |
| `config/prod.yaml` | Redaction on, OpenTelemetry, Redis, tighter budgets. | Before deploying. |
| `config/offline.yaml` | Fakes, for CI and for trying it without keys. | Rarely. |

**Access control.** If documents belong to different users, build the metadata
filter from the *authenticated* principal in `service/app.py` and pass it to the
retriever (`VectorRetriever(filter_from=...)`). Never derive it from the
question text: that is the RAG vulnerability that actually gets exploited.

## Deploy

```bash
docker build -t {{ project_name }} .
docker run -p 8000:8000 --env-file .env {{ project_name }}
```

The image runs `hardpoint serve` as a non-root user with `HARDPOINT_ENV=prod`.
Ingestion is a separate job -- `hardpoint ingest run`, on a schedule -- never part
of the request path, and it is safe to run while the service is serving.

## Evaluate it

```bash
hardpoint eval run --suite smoke                    # gate against evals/baselines/smoke.json
hardpoint eval run --suite smoke --max-cost 0.50    # refuses to start above the estimate
hardpoint eval run --suite smoke --cassettes record # record provider calls once...
hardpoint eval run --suite smoke --cassettes replay # ...then replay with zero calls in CI
hardpoint eval run --suite smoke --update-baseline  # accept the current run as the baseline
```

`evals/smoke.jsonl` holds one case per line. The committed baseline was recorded
with the offline fakes; once you switch to real models, run once with
`--update-baseline` and commit the result. A pull request that makes retrieval
worse fails the gate with a table of the questions that regressed. Judge metrics
(faithfulness, answer relevance) use `prompts/judge_*.md` and are enabled with
`eval.judge.enabled: true`.
